# 04 — 配置 JSON Schema

> 配置文件字段权威清单。改 GUI 或加新功能开关前查这里。

## 文件位置

JSON 文件放在仓库根目录,`main.py` 启动时加载 `default.json`。游戏专用配置:
- `default.json` — 默认模板
- `d4.json` / `d4_druid.json` — Diablo IV
- `poe2_锐眼.json` — 流放之路 2
- `tors10.json` — Torchlight Infinite
- `notepadtest.json` — 测试用

切换配置:GUI 顶部 "加载配置" 按钮。

## skills

技能配置字典,key 是技能名(`Skill1`-`Skill8` 等任意字符串)。

```json
"Skill1": {
  "Enabled": true,                  // 是否启用
  "Key": "1",                       // 主按键(支持序列 "delay50,1,delay100,2")
  "Priority": false,                // true=用 high 队列, false=用 normal
  "Timer": 1000,                    // TriggerMode=0 时的间隔(ms)
  "TriggerMode": 0,                 // 见下表
  "CooldownCoordX": 0,              // TriggerMode=1 时的冷却图标坐标
  "CooldownCoordY": 0,
  "CooldownSize": 12,               // 冷却图标边长(px)
  "ColorTolerance": 12,             // RGB 容差
  "ExecuteCondition": 0,            // 见下表
  "ConditionCoordX": 0,             // ExecuteCondition!=0 时的检测点
  "ConditionCoordY": 0,
  "ConditionColor": 0,              // 0=资源充足检测, 1=HP红色检测, >1=RGB相似度
  "AltKey": ""                      // ExecuteCondition=2 时备用按键
}
```

### TriggerMode 枚举

| 值 | 名 | 行为 |
|----|-----|------|
| 0 | **定时** | 按 `Timer` 间隔触发,`Key` 入队 |
| 1 | **冷却检测** | `cooldown_checker_interval` 周期内检测 `(CooldownCoordX, CooldownCoordY)` 区域,匹配度 ≥ 95% 视为就绪,就绪才触发 |
| 2 | **按住** | START/RESUME 时一次性 `hold_key(Key)`,STOP/PAUSE/配置热更新差异时 `release_key`。`hold_key` 走 normal 队列(priority=2),`release_key` 走 **emergency 队列**(priority=0)以防 stuck key —— 详见 wiki/03。配置变更时增量同步,不在循环中 |

### ExecuteCondition 枚举

| 值 | 名 | 行为 |
|----|-----|------|
| 0 | **无条件** | 直接执行 `Key` |
| 1 | **BUFF 限制**(buff 已存在则跳过) | 检测 `(ConditionCoordX, ConditionCoordY)` 像素 → 若**符合**(buff 在身上)则**不**执行 |
| 2 | **资源条件**(资源足够走主键) | 检测条件 → **符合**走 `Key`,**不符合**走 `AltKey`。带连续 2 帧确认避免抖动 |

### ConditionColor 枚举

| 值 | 含义 |
|----|------|
| 0 | "资源充足"判定:像素 RGB 极差 > `ColorTolerance` 视为资源条满足 |
| 1 | "HP红色"判定:`r>100 && g<50 && b<50` 视为 HP 在场 |
| ≥2 | RGB 相似度:与该数字(0xRRGGBB)比对,容差 `ColorTolerance` |

## global.window_activation

```json
"window_activation": {
  "enabled": true,
  "ahk_class": "Notepad++",         // 优先用类名匹配
  "ahk_exe": "notepad++.exe"        // 进程名(GUI 有"刷新进程列表"按钮)
}
```

⚠️ **两个字段不是等价的备选关系**,实际用途不同:

| 字段 | 用于 | 由谁读 |
|------|------|--------|
| `ahk_exe` | **截图目标窗口**:`BorderFrameManager._get_target_window_handle()` 用它(或 `ahk_class`)定位窗口去 DXGI 捕获 | Python |
| `ahk_class` | **AHK 输入目标**:`MacroEngine._on_config_updated` 仅在 `ahk_class` 非空时发 `set_target_window("ahk_class X")` 给 AHK,作为 `ControlSend` 的 `WinTitle` | AHK |

如果只配 `ahk_exe`(常见情况):
- ✅ 截图正常(Python 端按进程名找窗口)
- ⚠️ AHK 输入目标**不会被更新**,继续用启动时的 `AHKConfig.WINDOW_EXE` 默认值(`"notepad++.exe"`)。`direct` 模式不影响(SendInput 不需要目标),但 `control` 模式(ControlSend)会发到错误窗口

**推荐**:`direct` 模式只配 `ahk_exe` 即可;`control` 模式必须配 `ahk_class`。

## global.input_mode

```json
"input_mode": "direct"
```

| 值 | 含义 |
|----|------|
| `direct`(默认) | AHK 用 `SendInput`,需要游戏窗口前台激活 |
| `control` | AHK 用 `ControlSend`,后台发送(部分游戏不支持) |

由 `AHKCommandSender.set_send_mode(mode)` 在 F8 进 READY 时同步给 AHK。

## global.stationary_mode_config

原地模式 + 强制移动 + 互动。

```json
"stationary_mode_config": {
  "hotkey": "x",                                    // 切换原地模式的热键
  "mode_type": "shift_modifier",                    // 见下表
  "force_move_hotkey": "a",                         // 强制移动键(monitor 模式)
  "force_move_replacement_key": "f",                // 按住 a 期间非白名单/非紧急队列按键替换为 f
  "force_move_passthrough_keys": ["RButton", "space"]  // 白名单:这些键不被替换(位移技能)
}
```

`force_move_passthrough_keys` 字段:强制移动期间需要正常发送、不被替换为 `f` 的非紧急键。典型场景:
- **RButton 闪现/dash**(managed_keys 注册):用户在跑路时按 RButton 想位移,不希望被替换成捡装备
- **space 翻滚/dodge**(special_keys 注册):同理。注意 space 已经是 `~` 模式直达游戏,加入白名单只是为了语义一致和保险

匹配在 AHK 端不区分大小写。空列表/缺省 → 强制移动期间非紧急队列键都按原始行为替换。HP/MP 紧急药剂由 `IsEmergencyAction` 识别,**永远不被强制移动替换**,避免边跑路边把药剂发成 `f`。

### mode_type 枚举

| 值 | 行为 |
|----|------|
| `shift_modifier`(常用) | 原地模式激活时,所有 `SendPress(key)` 改为 `Send "+{key}"`(Shift+key) |
| `block_mouse` | 屏蔽鼠标移动(预留,未实装) |

### 强制移动 + 互动键(设计意图,**不是 BUG**)

按住 `force_move_hotkey`(默认 A)期间:
1. AHK 端 `ForceMoveActive=true`
2. 非白名单、非 HP/MP 紧急药剂的 `SendPress` 被替换成 `force_move_replacement_key`(默认 `f`)
3. 白名单键和 HP/MP 紧急药剂正常发送
4. 效果:角色边强制移动边不停发 `f`,自动捡装备/触发 NPC 对话(D4/PoE2 常用技巧),但仍可位移和喝药

如果你的游戏 `f` 键有别的功能,改 `force_move_replacement_key` 字段。

## global.resource_management

HP/MP 自动药剂。

```json
"resource_management": {
  "check_interval": 200,            // 资源检查间隔(ms)
  "hp_config": {
    "enabled": true,
    "key": "1",                     // 触发的按键
    "threshold": 50,                // 百分比阈值,< threshold 触发
    "cooldown": 5000,               // 内部冷却(ms),防过快连按
    "detection_mode": "rectangle",  // rectangle | circle | text_ocr

    // detection_mode=rectangle 时
    "region_x1": 100, "region_y1": 800,
    "region_x2": 250, "region_y2": 850,
    "tolerance_h": 10,              // HSV 容差
    "tolerance_s": 30,
    "tolerance_v": 50,

    // detection_mode=circle 时
    "center_x": 175, "center_y": 825,
    "radius": 80,
    "half": "left",                // 可选,只分析哪半边(避开被遮挡侧): left|right|full
                                   //   缺省: HP=left, MP=right (D4 中央球默认)
                                   //   PoE2 角落球: HP=right, MP=left (与默认相反)

    // detection_mode=text_ocr 时
    "text_x1": 97, "text_y1": 814,
    "text_x2": 218, "text_y2": 835,
    "ocr_engine": "template"        // template | keras | tesseract
  },
  "mp_config": { ... 同上 ... }
}
```

### detection_mode 枚举(性能数据基于 478 次基准)

| 值 | 算法 | 速度 | 成功率 | 备注 |
|----|------|------|--------|------|
| `rectangle`(推荐) | HSV 模板 + 连续段填充 | **0.3ms** | 100% | 96% 误差 < 5%,适合条形资源条 |
| `circle` | HSV 模板 + 半圆掩码 | ~5ms | 99%+ | 适合球形资源条(D4) |
| `text_ocr` | 数字 OCR | 25-241ms | 98-99% | 适合 PoE2 数字显示 |

### ocr_engine 枚举

| 值 | 速度 | 准确率 | 依赖 |
|----|------|--------|------|
| `template`(默认) | ~25ms | 98.3% | 无额外依赖(用预生成数字模板) |
| `keras` | ~99ms | 98.5% | deepai 模块,首次启动加载 ~2s |
| `tesseract` | ~241ms | 99.0% | Tesseract OCR(`tesseract_ocr.tesseract_cmd` 配置路径) |

## global.priority_keys

特殊键 + 管理键的高级配置。

```json
"priority_keys": {
  "enabled": true,
  "special_keys": ["space"],         // special 模式 Hook(透传 + 状态监控)
  "managed_keys": {                  // priority 模式 Hook(拦截+映射+延迟,程序代按)
    "e": {
      "target": "shift",             // 把 e 映射成 shift(避免自拦截)
      "delay": 50,                   // 前后各 50ms delay 保证时序
      "hold_ms": 0                   // 可选:>0 时按 hold→delay→release 节奏发,模拟物理按住
    },
    "RButton": {
      "target": "RButton",           // target=自身时,只是为了享受 delay 保护
      "delay": 25
    },
    "c": {
      "target": "c",                 // 大招类:前置 delay 等 LButton 动画收尾
      "delay": 75,
      "hold_ms": 25
    }
  }
}
```

**按键命名约定**: `priority_keys` 的 key 和 `target` 都保存为 AHK 标准按键名。鼠标键使用 `LButton` / `RButton` / `MButton`;GUI 可接受 `left_mouse` / `right_mouse` / `middle_mouse` 等别名输入,但保存时会归一化为 AHK 标准名。

### special_keys vs managed_keys

| 属性 | special_keys | managed_keys |
|------|--------------|--------------|
| AHK Hook 模式 | `special`(`~` 前缀) | `priority`(`$` 前缀) |
| 是否拦截 | ❌ 透传给游戏 | ✅ 完全拦截后程序代按 |
| 清非紧急队列 | ❌ 仅过滤(但 `release:*` 与 HP/MP 仍放行,见 `IsAllowedDuringPause`) | ✅ 立即清 |
| 保护期 | 按住期间 | delay + hold + delay 窗口 |
| 配置类型 | 字符串列表 | `{ target, delay, hold_ms? }` 对象 |
| 用例 | 闪避(Space) | 闪现 / 强力技 / 大招(RButton/E/C) |

**为什么管理键要 target+delay+hold_ms**:
- `target` 防止 AHK 端的 `$E` Hook 自己拦截自己 SendInput 出来的 `E`
- `delay` 给游戏后摇时间,避免连续技能冲突。**前置 delay 还可以让正在播放的 LButton 自动键动画在 c 大招按下前收尾**,这是 ARPG 大招最重要的语义
- `hold_ms` >0 时把单次 press 改成 `hold:target` → `delay_clear:hold_ms` → `release:target`,模拟物理按住,对要求长按检测的游戏更稳
- 完成时发 `managed_key_complete` 事件让 Python 恢复调度器

**跨类冲突防御**:同一个 key 不能同时声明在 special_keys 和 managed_keys,Python 注册时检测到重复会 LOG_ERROR 并跳过后注册者(`registered_business_keys` set 跟踪)。

### 字面加号键 `target="+"`

如果某个管理键想发字面加号键(`{+}`),AHK 端会正确识别(`StrLen(key)=1` 时认为是字面键,长度>1 且首字符是 `+` 才认为是 Shift 修饰符前缀)。

## global.debug_mode

```json
"debug_mode": { "enabled": false }
```

`enabled=true` + `READY/RUNNING/PAUSED` 状态:
- 显示 `DebugOsdWindow` 调试 OSD(技能匹配度、HP/MP 百分比、检测区域可视化)
- `RUNNING` 状态启动数据采集
- `READY/PAUSED` 显示但不采集

`set_debug_mode()` 同时把 `AHKInputHandler.dry_run_mode` 切换:为 `True` 时不真发按键,只记录到 OSD。

```json
"affix_reroll": {

  "target_affixes": ["生命", "暴击"],

  "click_delay": 200,
```

## 配置变更如何同步到 AHK

当你在 GUI 改配置后:

1. UI widget 收集 → `ui:save_full_config_requested` 事件
2. `MacroEngine.save_full_config` 写文件 + 发 `engine:config_updated`
3. 各 manager 订阅 `engine:config_updated`:
   - `SkillManager.update_all_configs / update_global_config` 重组调度任务
   - `ResourceManager.update_config` 更新 HP/MP 配置
   - `BorderFrameManager._on_config_updated` 更新窗口配置
4. `MacroEngine._on_config_updated` 还会:
   - `set_force_move_key / set_force_move_replacement_key` 同步给 AHK
   - `_update_ahk_emergency_keys_cache` 调用 `batch_update_config` 更新 HP/MP 缓存键

热重载完成,无需重启程序。

## 创建新配置文件的快捷方式

GUI "保存配置" 按钮会弹保存对话框。或手动:

```bash
cp default.json my_game.json
# 用编辑器调字段
python main.py
# GUI 内"加载配置"选 my_game.json
```

JSON 文件在 GUI 加载时会通过 `ConfigManager.load_config` 解析,语法错误会写日志(主窗口看不到错误,看 stderr)。
