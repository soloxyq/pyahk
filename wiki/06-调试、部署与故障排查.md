# 06 — 调试、部署与故障排查

> 出问题先看这里。从日志位置到常见 BUG 排查路径,实用清单。

## 1. 调试日志开关

`debug_log.py` 三个 API:
```python
LOG_INFO("...")     # 总是输出
LOG_ERROR("...")    # 总是输出到 stderr
LOG("...")          # 只在 DEBUG=1 时输出(高频日志用)
```

详细 `LOG()` 由进程启动时的环境变量决定；PowerShell 用:

```powershell
$env:DEBUG = "1"
python main.py
```

GUI 顶部的 `DEBUG MODE` 复选框是另一个运行配置，它不会在进程中途
改变上述环境变量或已绑定的 `LOG` 函数。该复选框会:
- 启用 `dry_run_mode`(按键不真发,只记录)
- READY/RUNNING/PAUSED 时显示 `DebugOsdWindow`(技能/资源可视化)

运行中复选框会置灰；必须先按 F8 回到 STOPPED 再切换。这样 Python 的
调试状态与 AHK 中已经运行的宏/持键不会在半轮运行中失配。

## 2. OSD 窗口

### OSDStatusWindow(`status_window.py`)

主状态显示:READY/RUNNING/PAUSED 文字 + 颜色。RUNNING/PAUSED 且配置了 `boss_mode_hotkey` 时会附带 `BOSS:开/关`。点不到、不抢焦点(`WA_TransparentForMouseEvents` + `WA_ShowWithoutActivating`)。

窗口标题 `TorchLightAssistant_OSD_12345` —— **AHK 用这个标题查找窗口发事件**。
改名时要同步修改 `status_window.py` 中的窗口标题和
`hold_server_extended.ahk` 中的目标标题；`ahk_event_filter.py` 不保存窗口标题。

### DebugOsdWindow(`debug_osd_window.py`)

DEBUG MODE 启用时显示。内容:
- 当前 HP/MP 百分比
- 各启用技能的实时匹配度 + 是否就绪
- 检测区域可视化(冷却小框、HP/MP 区域、条件检测点)
- dry_run 模式下的虚拟按键流

## 3. AHK 服务器调试

AHK 子进程启动时**不弹任何 GUI**(`gui1.Hide()`)。要调试它:

### 看 AHK 是否在跑

```powershell
# Windows 任务管理器搜 "AutoHotkey64"
# 或:
Get-Process | Where-Object {$_.ProcessName -like "*AutoHotkey*"}
```

### 让 AHK 输出日志

`hold_server_extended.ahk` 默认无日志。要调试时,在关键位置加:

```ahk
; 临时调试: 写入脚本目录下的文件
FileAppend "[" A_Now "] HandleManagedKey: " key "`n",
    A_ScriptDir "\ahk_debug.log", "UTF-8"
```

或重启 TrayTip:
```ahk
; 文件尾部默认注释了:
TrayTip("AHK输入系统已启动", "hold_server_extended.ahk", 1)
```

### 手动停 AHK 进程

正常退出时 Python 先发送 `CMD_SHUTDOWN`，让 AHK 释放全部持键并自行退出；
等待超时后才依次回退 `terminate()` / `kill()`。如果 Python 进程硬崩溃，
来不及走这条清理链，AHK 可能残留:

```powershell
# 先核实命令行，区分本项目服务和用户的其他 AHK 脚本
Get-CimInstance Win32_Process -Filter "Name = 'AutoHotkey64.exe'" |
    Select-Object ProcessId, CommandLine
# 确认后仅对本项目的 PID 执行 Stop-Process -Id <已核实的PID>
```

或右键 AutoHotkey 托盘图标退出。`gui1.Hide()` 隐藏的是 WM_COPYDATA
服务窗口，不是托盘图标；为排查显示 `gui1` 也不是退出所必需。

## 4. WM_COPYDATA 通信验证

排查 Python ↔ AHK 通信问题:

```powershell
# 1. 验证 AHK 进程存在（服务 GUI 是隐藏窗口，MainWindowTitle 不可作为依据）
Get-Process | Where-Object {$_.ProcessName -like "*AutoHotkey*"}

# 2. Python PING 同时验证隐藏窗口查找和 WM_COPYDATA 协议
python -c "from hold_client import send_ahk_cmd; print(send_ahk_cmd('HoldServer_Window_UniqueName_12345', 1))"
# True = AHK 正常响应; False = 找不到窗口或 AHK 不响应
```

- `ahk_config.py` 里 `AHK_PATH` 是否正确
- `hold_server_extended.ahk` 是否在仓库根(`AHKConfig.SERVER_SCRIPT`)
- 重新启动 main.py(它会拉新进程)

## 6. 行尾(LF / CRLF)

仓库已加 `.gitattributes` 强制 `* text=auto eol=lf`。但 WSL 编辑器仍可能保存为 CRLF。

### 验证

```bash
# 看单文件
file <path>          # "Unicode text" 无 CRLF 标记 = LF; "with CRLF line terminators" = 坏

# 看是否有 trailing whitespace
git diff --check HEAD -- <path>

# 看真实改动规模(忽略行尾)
git diff --stat --ignore-space-at-eol HEAD
```

### 修复 CRLF

```python
# 用 Python 最稳(sed 在 WSL 偶尔静默失败)
import sys
for f in sys.argv[1:]:
    with open(f, 'rb') as fp: data = fp.read()
    if b'\r\n' in data:
        with open(f, 'wb') as fp: fp.write(data.replace(b'\r\n', b'\n'))
        print(f'fixed: {f}')
```

存为 `fix_eol.py`,然后 `python fix_eol.py path1 path2 ...`。

## 7. 常见 BUG → 排查路径

### BUG: 按 F8 没反应,主窗口没消失

**可能原因**:
1. AHK 没启动(F8 Hook 没注册)
2. F8 被其他程序占用(如 NVIDIA 录制)
3. Python 主窗口标题被改过,AHK 找不到

**排查**:
```powershell
# AHK 在跑吗
Get-Process | Where-Object {$_.ProcessName -like "*AutoHotkey*"}

# 通信窗口是否响应（只读探测，不要用 HOOK_REGISTER 做诊断）
python -c "
from hold_client import send_ahk_cmd
print('PING:', send_ahk_cmd('HoldServer_Window_UniqueName_12345', 1))
"
```

### BUG: 状态切到 RUNNING 但技能不发

**可能原因**:
1. `window_activation` 配错，direct 模式的前台校验失败，或 control 模式找不到目标
2. `dry_run_mode` 仍开着(GUI 顶部 DEBUG MODE 打勾会自动开)
3. AHK 运行时闸门仍关闭、owner/epoch 不匹配，或 direct 模式的目标前台校验失败

**排查**:
```powershell
$env:DEBUG = "1"
python main.py
# 观察日志:
# [AHK输入][DEBUG] send_key called with: q   ← 表示 Python 发出去了
# 没看到 = SkillManager 没调
# 看到 = AHK 收到但没发(看 dry_run / window_activation)
```

**模板未截**也常见。F8 必须在游戏正常状态(满 HP/MP/技能就绪)按,否则:
```
[ResourceManager] 未找到模板缓存: hp_region,请先按F8初始化
```

### BUG: HP 低了不喝药

**可能原因**:
1. `resource_management.hp_config.enabled=false`
2. `threshold` 设太低(如 10),实际不会跌到那么低
3. `cooldown` 还没过(`time.monotonic` 控制)
4. **序列模式下 resource_checker 漏注册**(2025 已修,B1)
5. detection_mode=text_ocr 但 OCR 引擎初始化失败

**排查**:
```python
# DEBUG=1 看周期日志
# [HSV检测] hp_region - 匹配详情: 区域大小=150x50, 填充行数=18/50, 匹配度=36.00%
# 36% < threshold(50) 应该触发
# 看下一行有没有 "已执行HP资源 - 按键: 1"
```

### BUG: 按住 A 不停发 f 键

**这不是 BUG,是设计意图**(强制移动 + 互动)。详见 [02-架构与通信](02-架构与核心概念.md) 的"设计意图"段。

按住 `force_move_hotkey` 时,非白名单、非 HP/MP 的自动 `SendPress` 会被替换成 `force_move_replacement_key`。如果某些自动键必须保留,显式写入 `stationary_mode_config.force_move_passthrough_keys`。

注意: `priority_keys.special_keys` 不会自动加入强制移动白名单。特殊键只表示“用户物理按下时透传并让自动系统让路”;白名单表示“强制移动期间程序自动发该键时不替换”。

如果不需要这个功能:把 `force_move_hotkey` 清空即可禁用强制移动监控。仅清空 `force_move_replacement_key` 不会禁用替换,AHK 收到空串会回到默认 `f`。

### BUG: 技能序列 "q,delay100,w" 中 w 不发

**可能原因**(2025 修复):
- 历史 BUG #2:序列展开后,delay 期间 `ClearNonEmergencyQueues()` 把 w 清掉了
- 已修:普通 sequence delay 转为本队列队首的 `seqrun:` 等待项(`notBefore`),只阻塞自己的优先级队列
- 验证:`NextToExecuteQueueName()` 会跳过 `notBefore` 未到的队列;管理键独占延时单独使用 `ManagedDelayUntil`

当前通用宏模式不再依赖旧 `sequence_timer_interval`;若宏太快,请在 `macro_steps` 里显式加入 `delay` 步骤。

### BUG: 原地模式按技能键完全没反应

**可能原因**(2025 修复):
- 历史 BUG #2:`SendDirect` 对 `+1`(Shift+1)发送 `Send "{+1}"` 是非法 AHK 语法
- 已修:`SendDirect` 检查 `StrLen(key) > 1 && SubStr(key, 1, 1) = "+"` → `Send "+{" SubStr(key, 2) "}"`

### BUG: PAUSED 后恢复 RUNNING,旧技能动作残留爆发

**可能原因**(2025 修复):
- 历史 BUG:`ClearQueue` 没声明 `EmergencyQueue/HighQueue/NormalQueue/LowQueue` 为 global → 赋值 `[]` 实际创建局部变量,全局队列旧动作还在
- 已修:`ClearQueue` 顶部加齐 global 声明
- 验证:跑第 5 节的 global 完整性自检脚本

### BUG: TriggerMode=2 按住模式下,Space 闪避或 F8 退出后键卡住

**可能原因**(2025 修复 — 三层防御):
- **历史 BUG #1**:`release_key()` 走 normal 队列,会被 managed key 的 `delay_clear` 期间的 `ClearNonEmergencyQueues()` 清掉 → 游戏里键被永久按住
- **历史 BUG #2**:`SpecialKeysPaused` 期间 `ProcessQueue` 只扫每个队列队首,如果队首是普通 `press:*`,后面的 `release:*` 会被埋住
- **历史 BUG #3**:STOPPED 路径里 `clear_all_configurable_hooks()` 把 `~space` hook 注销后,AHK 永远收不到 Space up 事件 → `SpecialKeysPaused` 卡 true → 后续 `release:*` 被卡

**当前修复(声明式账本 + 清理兜底)**:
1. TriggerMode=2 通过 `CMD_SET_SKILL_HOLD_KEYS` 声明完整期望集合,AHK 独占维护实际持键,不再把 down/up 拆进普通队列
2. PAUSED/STOPPED 的运行时关闸与 `ClearQueue(-1)` 会直接释放技能持键、管理键临时持键和宏持键
3. 队列兼容路径中的 `release:*` 仍由 `IsAllowedDuringPause(action)` 放行,避免临时 hold 被特殊键压住
4. `UnregisterHook(special)` 同步从 `SpecialKeysPressed` 删除该 key,若全空则 `SpecialKeysPaused→false` 并发 `special_key_pause:end` 给 Python;`ClearAllConfigurableHooks()` 末尾兜底再做一次

**验证**:`hold_server_extended.ahk` 内
- `IsAllowedDuringPause` 函数存在
- `ClearQueue(-1)` 内有 `ManagedDelayUntil := 0; ActiveManagedKeys := Map()`
- `UnregisterHook(special)` 分支有 `SpecialKeysPressed.Delete(key)` 与 pause 状态归零
- TriggerMode=2 通过 `CMD_SET_SKILL_HOLD_KEYS` 声明完整期望集合,AHK 端 `ClearQueue(-1)` 直接释放账本中的持键

### BUG: F9/Z 已进入寻路运行态,但没有移动点击

1. 确认游戏目标窗口仍在前台；寻路使用物理屏幕点击,后台时会主动拒绝
2. 检查 `window_activation.ahk_exe/ahk_class` 能否解析到有效 HWND
3. 查看日志是否有“目标窗口无效 / 目标窗口不在前台 / 客户区无效”；
   AHK 执行队列动作时还会复核点击坐标仍在当前客户区的半开边界内
4. 不要按 1920×1080 的 `(960,540)` 排查；实现以目标窗口客户区动态计算中心
5. 若刚执行过 stop/start,检查“第 N 代线程停止超时”日志；旧代结果会被丢弃,
   不会补发到新一代

### BUG: WSL 改完代码 git diff 显示 99 个文件

**症状**:你只编辑了 1-2 个文件,git status 却列出几十个 modified。

**原因**:WSL 把 LF 改成了 CRLF。

**修法**:第 6 节。

### BUG: AHK 进程崩溃不重启

**当前设计**:不做自动重启。AHK 是单点,崩了系统拒绝运行(见 docs/AHK_COMPLETE_ARCHITECTURE.md)。运行期命令发送失败时,`AHKInputHandler` 会探测子进程是否已退出,首次发现会发 `ahk_process_died` 事件,MacroEngine 延后切到 STOPPED 并告警。

边界:这不是空闲 watchdog。AHK 若在 READY/STOPPED 空闲时崩溃,要等下一次发送命令才会被发现。也没有 OS 级 `SendInput` 解卡兜底,AHK 已死时可能残留持久按住键。

**排查**:
1. PowerShell 看 Windows 事件查看器,搜"AutoHotkey64.exe"崩溃记录
2. 在 AHK 脚本里加 `try/catch` 包关键函数
3. 如需空闲秒级发现,再加主线程 QTimer watchdog；当前主线未启用

## 8. 性能问题排查

### CPU 高

```powershell
$env:DEBUG = "1"
python main.py
# 看 [统一调度器] 日志,几个间隔配置:
#   cooldown_checker_interval (缺省回退 100ms)
#   capture_interval (缺省回退 40ms)
#   resource check_interval (缺省回退 200ms)
```

调大间隔(如 cooldown 100→200)立刻降 CPU。

### UI 卡顿

- 关掉 DEBUG MODE(OSD 渲染消耗大)
- 检查 `[事件总线性能]` 日志的 events/s,> 50 可能有事件风暴
- 看 `border_manager.start_capture_loop` 日志确认 capture_interval

### 帧率不稳

- C++ 捕获间隔 `capture_interval_ms`(C++ 内部) vs `BorderFrameManager.start_capture_loop(interval_ms=)`,确认一致
- DXGI 在某些笔记本会被独显/集显切换打断(`pause_capture` 时观察是否丢帧)

## 9. 部署清单

打包发布给非开发用户时:

1. **Python 环境**:用 `pyinstaller` 或同类工具打包 main.py,带上 `requirements.txt` 的所有依赖
2. **C++ 库**:`native_capture/capture_lib.dll` 必须和 .py 同目录
3. **AutoHotkey**:不打包,要求用户先装 AHK v2(`https://www.autohotkey.com/v2/`)
4. **配置路径**:在 `ahk_config.py` 把 `AHK_PATH` 改成 `r"C:\Program Files\AutoHotkey\v2\AutoHotkey64.exe"`(常见安装位置)
5. **Tesseract**(可选):`pytesseract` 已在 Python 依赖中；用户用
   text_ocr/tesseract 时还需安装系统级 Tesseract 并配置可执行文件路径
6. **文档**:`AGENTS.md` + `wiki/01-项目概述与快速入门.md` 给最终用户

## 10. 升级与回滚

升级 AutoHotkey 版本:
- AHK v2.0 → v2.1+: 检查 `hold_server_extended.ahk` 的 `#Requires` 行,语法可能微变
- 运行第 5 节的全文扫描，验证所有函数的 global 声明

升级 PySide6:
- 6.5 → 6.7+: `QAbstractNativeEventFilter` 签名稳定,但 `nativeEvent` 个别方法签名有变,看 `ahk_event_filter.py` 是否需要适配

回滚:
```powershell
git log --oneline | Select-Object -First 20    # 找到目标 commit
git checkout <commit>
```

但**别回滚到 master 或 2025.10.16 之前的提交** —— 那时还是 pynput 架构,所有架构假设都不一样。

## 11. 测试 Checklist(改完代码后)

先从仓库根目录跑自动化检查；真 AHK/Windows 专属用例在环境
不满足时会按各测试的 skip 条件跳过:

```powershell
python -m pytest -q
python tests/test_ahk_global_scope.py
git diff --check HEAD
```

然后执行下列需要真游戏窗口/物理输入的手工检查:

Qt 测试必须共享 `QApplication`，即使当前用例只验证事件循环也不能先创建
`QCoreApplication`：后续 QWidget 用例无法把已存在的应用单例升级为 GUI 应用，
可能直接终止进程而没有普通 Python 异常。这曾造成分段通过、全量联跑退出，
不能仅因退出位置靠近 OCR 用例就归因于 PaddleOCR。

| 测试 | 怎么做 | 期望 |
|------|--------|------|
| F8 启动 | 按 F8 | STOPPED → READY,主窗口隐藏,OSD 出现 |
| Z 启动 | 在 READY 按 Z | READY → RUNNING,听到提示音 |
| Z 暂停 | 在 RUNNING 按 Z | RUNNING → PAUSED,所有按键停 |
| Z 恢复 | 在 PAUSED 按 Z | PAUSED → RUNNING,**无积压动作爆发** |
| F8 退出 | 在任意非 STOPPED 按 F8 | → STOPPED,主窗口出现 |
| 通用宏 | 配 `press q → delay100 → press w`,启动 | AHK 宏循环完整 q→等→w;显式 delay 决定步间隔,5ms 仅为轮询预算 |
| HP 自动药 | 配 hp_config + threshold,游戏掉血 | < threshold 时按 hp.key |
| 管理键 + HP | 配 e:shift, 同时 HP 低 | E 触发期间 HP 仍能喝药 |
| 原地模式 | 配 shift_modifier,按 X 激活后按 1 | 实际发 Shift+1 |
| 强制移动 | 按住 A,并配 force_move=a / replacement=f / 白名单 RButton | 按住期间普通技能键变 f,白名单与 HP/MP 药剂仍发原键 |
| BOSS 模式 | 配 boss_mode_hotkey + 某技能 BossOnly | OSD 显示 BOSS:关时该技能跳过,切到开后按规则触发 |

自动化和上述手工用例均通过，才完成本轮主流程回归；不代表覆盖所有游戏/驱动环境。
