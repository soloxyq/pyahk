# 02 — 架构与通信

> 改核心模块前必读。本文用最少篇幅讲清 5 件事:进程拓扑、状态机、WM_COPYDATA 协议、4 级队列、5 种 Hook 模式。

## 1. 进程拓扑

pyahk 是**双进程架构**:

```
┌─ Python 进程(PySide6 GUI) ─┐         ┌─ AHK 子进程 ─┐
│   决策、图像分析、UI         │         │  键盘拦截、  │
│                               │ WM_COPY │  队列处理、  │
│                               │←──DATA─→│  SendInput   │
└──────────────────────────────┘         └──────────────┘
       PID = main.py                         PID = AutoHotkey64.exe
                                             (Python 启动时 fork)
```

**职责切分原则**:
- Python:屏幕捕获 → 模板匹配 → 条件判断 → 决定要按什么键 → 发命令
- AHK:接命令入队 → 按优先级取出 → SendInput 给目标窗口
- AHK 还负责:拦截全局热键(F8/F7/F9/Z 等)→ 通知 Python

**为什么这样切**:Python 的 hook 库(pynput) 在 Windows 上有 suppress 卡死问题,AHK 的 `$` 前缀 hook 完美规避自拦截。Python 专心做"思考",AHK 专心做"动手"。

## 2. 状态机

```
        ┌──────────┐  F8   ┌────────┐   Z    ┌─────────┐
        │ STOPPED  │←─────→│ READY  │───────→│ RUNNING │←──┐
        │          │       │        │        │         │   │ Z
        └──────────┘       └────────┘        └─────────┘   │
              ▲                                  │  Z      │
              │                                  ▼         │
              │                              ┌────────┐    │
              └─── F8 (从任意非 STOPPED) ─── │ PAUSED │────┘
                                              └────────┘
```

定义在 `torchlight_assistant/core/states.py`:
```python
class MacroState(Enum):
    STOPPED = "stopped"
    READY = "ready"
    RUNNING = "running"
    PAUSED = "paused"
```

`MacroEngine.VALID_TRANSITIONS` 严格限制转换:STOPPED 只能去 READY,READY 只能去 RUNNING/STOPPED,等等。非法转换被 `_set_state()` 拒绝。

**每个状态的副作用**(进入时):
- **STOPPED**:清理所有动态 Hook(F8/F7/F9 永久根热键保留),停止 SkillManager/ResourceManager/BorderManager,但**不杀 AHK 进程**
- **READY**:注册 Z + 业务热键(原地模式键、强制移动键、BOSS 模式键、特殊键、管理键), 激活目标窗口,捕获一帧用于初始化模板缓存和 PaddleOCR 数字框锁定(F7/F9 不在此处注册,见下文"永久根热键")
- **RUNNING**:启动 BorderManager 循环捕获,SkillManager 启动统一调度器
- **PAUSED**:`clear_queue(-1)` 全清队列,所有 manager 暂停

**模式互斥** (`_prepared_mode`):
- `combat`:F8 进入,跑技能/资源
- `pathfinding`:F9 进入 READY 准备态,Z 进入 RUNNING 后才跑寻路
- 洗练(F7) 不进入状态机,仅在 STOPPED 状态可启动

### 永久根热键 vs 动态热键

`MacroEngine._setup_primary_hotkey()` 启动时永久注册 **F8 / F7 / F9**:
- F8:STOPPED ↔ READY
- F7:handler 检查 `_state == STOPPED` → 启动洗练; 非 STOPPED 则忽略
- F9:STOPPED 且洗练未运行 → 设 `_prepared_mode = pathfinding` 并转入 READY 准备态(`prepare_border_only`),`PathfindingManager` 实际启动要等 Z 触发 READY → RUNNING;非 STOPPED 且当前为 pathfinding → 停止(转 STOPPED);combat 模式或洗练运行中 → 忽略

这三个键即使进 STOPPED 状态也保留(AHK 端 `RegisterHook` 把它们排除在 `RegisteredHooks` 外,所以 `ClearAllConfigurableHooks` 不会清),保证用户随时可触发。

`_register_secondary_hotkeys()` 只在 READY 时注册 **Z + 业务热键**(原地模式键、强制移动键、BOSS 模式键、特殊键、管理键、RButton 等),进 STOPPED 时全部清掉。

## 3. WM_COPYDATA 通信协议

### 3.1 Python → AHK(命令)

入口:`hold_client.send_ahk_cmd(window_title, cmd_id, param)`,首次查找窗口句柄后**永久缓存**(实测 0.069ms 单次)。

```python
# torchlight_assistant/config/ahk_commands.py
CMD_PING                       = 1
CMD_SET_TARGET                 = 2    # "ahk_exe game.exe"
CMD_ACTIVATE                   = 3
CMD_ENQUEUE                    = 4    # "priority:action"  e.g. "2:press:q"
CMD_CLEAR_QUEUE                = 5    # -1=全部, -2=非紧急, 0-3=单优先级
CMD_PAUSE                      = 6
CMD_RESUME                     = 7
CMD_HOOK_REGISTER              = 8    # "key:mode"  e.g. "F8:intercept"
CMD_HOOK_UNREGISTER            = 9
CMD_SEND_KEY                   = 10
CMD_SEND_SEQUENCE              = 11
CMD_SET_STATIONARY             = 12   # "true:shift_modifier" / "true:block_mouse"
CMD_SET_FORCE_MOVE_KEY         = 13
CMD_SET_FORCE_MOVE_STATE       = 14   # "true"/"false"
CMD_SET_MANAGED_KEY_CONFIG     = 15   # "key:target:delay[:hold_ms]"
CMD_CLEAR_HOOKS                = 16   # 清所有可配置 Hook(保留 F8/F7/F9)
CMD_SET_FORCE_MOVE_REPLACEMENT_KEY = 17
CMD_SET_PYTHON_WINDOW_STATE    = 18   # "main"/"osd",决定 AHK 往哪个窗口发事件
CMD_BATCH_UPDATE_CONFIG        = 19   # "hp_key:1,mp_key:2,stationary_type:..."
CMD_SET_SEND_MODE              = 20   # "direct"(SendInput) / "control"(ControlSend)
CMD_SET_FORCE_MOVE_PASSTHROUGH_KEYS = 21  # "RButton,space"
CMD_SET_MACRO_STEPS            = 22   # AHK 端宏步骤 line protocol: "type:data\n..."
CMD_START_MACRO                = 23   # 启动 AHK 端宏循环
CMD_STOP_MACRO                 = 24   # 停止宏循环并释放宏持键
```

> **AHK 端必须同步**:`ahk_commands.ahk` 与 `torchlight_assistant/config/ahk_commands.py` 的 ID 必须一一对应。新增命令时两处都要改。

### 3.2 AHK → Python(事件)

AHK 用 `SendEventToPython(event)` 发,目标窗口根据 `CurrentPythonWindow`(由 CMD_SET_PYTHON_WINDOW_STATE 控制)决定:
- `STOPPED` 状态 → main 窗口(`TorchLightAssistant_MainWindow_12345`)
- `READY/RUNNING/PAUSED` → OSD 窗口(`TorchLightAssistant_OSD_12345`)

Python 侧由**全局**事件过滤器接收:
```python
# torchlight_assistant/core/ahk_event_filter.py
class AHKEventFilter(QAbstractNativeEventFilter):
    def nativeEventFilter(self, eventType, message):
        # 解析 WM_COPYDATA → 通过 ahk_signal_bridge 发信号
        # 不消费消息,允许窗口默认过程继续
```
在 `main.py` 创建 QApplication 后立刻 `app.installNativeEventFilter(...)`,保证 attach 到 app 防 GC。

> 历史:之前 main_window 和 OSD 各自实现 nativeEvent 接收,有重复代码和潜在的"同一事件被处理两次"的风险。2025 重构改为单一接收点。

事件格式 `event_type:data`:

| 事件 | 触发场景 | data |
|------|---------|------|
| `intercept_key_down` | 拦截型热键(F8/F7/F9/Z 等)按下 | 键名 |
| `special_key_down` / `_up` | 特殊键(Space)按下/释放 | 键名 |
| `special_key_pause` | 特殊键引发的整体暂停状态切换 | `start`/`end` |
| `managed_key_down` | 管理键(E)按下 | 键名 |
| `managed_key_complete` | 管理键完成(delay+按键已发完) | 键名 |
| `monitor_key_down` / `_up` | 监控键(强制移动键 A) | 键名 |

事件路由:`AHKEventFilter` → `ahk_signal_bridge.ahk_event` Signal → `AHKInputHandler._on_ahk_event` → `event_bus.publish(event_type, ...)` → `MacroEngine` 各 handler。

## 4. 5 种 Hook 模式(AHK 侧)

由 `CMD_HOOK_REGISTER` 注册时指定模式:

| 模式 | AHK 前缀 | 拦截 | 释放事件 | 用途 | 例 |
|------|---------|------|---------|------|-----|
| **intercept** | `$` | ✅ 完全拦截 | ❌ | 系统热键、技能键 | F8/F7/F9/Z/原地模式键 |
| **priority**(管理键) | `$` | ✅ 完全拦截 | ❌ | 拦截后映射+加 delay,程序代按 | RButton 闪现 / E → Shift |
| **special** | `~` | ❌ 透传 | ✅ | 状态监控,激活时丢弃非紧急队列 | Space 闪避 |
| **monitor** | `~` | ❌ 透传 | ✅ | 仅状态跟踪 | 强制移动键 A |
| **block** | `$` | ✅ 完全屏蔽 | ❌ | 禁用某键 | 极少用 |

**`$` 前缀的关键作用**:防止 AHK 自己发的 SendInput 被自己的 hook 再次拦截(自拦截)。这是 Python pynput 时代的核心痛点,AHK 用 `$` 完美解决。

## 5. 4 级优先队列

定义在 `hold_server_extended.ahk` 顶部:

```ahk
global EmergencyQueue := []   ; 0 - 紧急(HP/MP 药剂、管理键 delay、TriggerMode=2 按住模式 release)
global HighQueue := []        ; 1 - 高(优先级技能)
global NormalQueue := []      ; 2 - 普通(常规技能/序列)
global LowQueue := []         ; 3 - 低(UI/拾取/辅助)
```

`SetTimer(ProcessQueue, 20)` 每 20ms 调度一次。

### 取队规则

| 系统状态 | Emergency | High/Normal/Low |
|---------|-----------|-----------------|
| 正常运行 | 优先取 | 按优先级取 |
| `IsPaused=true`(用户 Z 暂停) | **仍取** | 暂停 |
| `SpecialKeysPaused=true`(Space 按住) | **仍取** | **只取安全动作**(`IsAllowedDuringPause`:HP/MP 紧急药剂 OR `release:*` 释放动作,后者防止 TriggerMode=2 按住键卡死) |
| `DelayUntil > 0` 且 `DelayClearOthers=true` | 等 delay | **被清空** |
| `DelayUntil > 0` 且 `DelayClearOthers=false` | 等 delay | 等 delay |

> **DelayUntil 期间的 emergency 特例**:当前实现会在 delay 未结束时扫描 emergency 队列,只放行 `IsEmergencyAction()` 识别出的 HP/MP 药剂,避免长 delay 压住救命药。`release:*` 不在 delay 中提前放行,防止管理键 hold 序列被打乱。
>
> **`DelayClearOthers` 为什么重要**:管理键(E)按下后会 `EnqueueAction(0, "delay_clear:50")`,期间清非紧急队列以保证管理键独占;而普通 sequence 比如 `q,delay100,w` 中的 delay 是 `EnqueueAction(2, "delay:100")`,不应该清掉同序列后续的 w。
>
> **`ClearQueue(-1)` 同步重置 DelayUntil/DelayClearOthers/ActiveManagedKeys**:全清队列后保留旧 delay 状态语义不干净,且会让 PAUSED→RESUME 时新入队的 `hold:N` 被旧 `DelayClearOthers` 期间的 `ClearNonEmergencyQueues()` 清掉,造成按住模式 stuck。所以 `ClearQueue(-1)` 必须把这三者也归零。

### 入队展开 sequence

`EnqueueAction(priority, action)` 拦截 `sequence:` 类型,展开成原子动作:
```
sequence:q,delay100,w
  ↓ 展开
EnqueueAction(2, "press:q")
EnqueueAction(2, "delay:100")
EnqueueAction(2, "press:w")
```
这样复用 `DelayUntil` 异步机制,**不再有同步 Sleep 阻塞**(2025 修复)。

### AHK 端通用宏解释器

`sequence_enabled=true` 的通用宏不再由 Python 调度器逐步执行。流程是:

1. Python 从 `global.macro_steps` 读取步骤(`down/up/press/delay`),通过 `CMD_SET_MACRO_STEPS=22` 下发给 AHK。
2. READY→RUNNING 时 Python 发 `CMD_START_MACRO=23`。
3. AHK `MacroTick` 每 5ms 推进宏状态机,顺序执行步骤并循环;`delay` 用 `MacroDueTime` 等待。
4. PAUSED/STOPPED/配置切换时 Python 发 `CMD_STOP_MACRO=24`,AHK 端按 LIFO 释放仍按住的宏键。

这条路径独立于 4 级队列和 `DelayUntil`,因此 `down` 与 `up` 不会因为 normal/emergency 队列优先级交错而乱序。

## 6. 设计意图(易被误判为 BUG)

| 行为 | 真相 |
|------|------|
| 强制移动键(默认 A)按住时,非白名单/非 HPMP 的自动 `SendPress` 被替换为 `f` | 边跑边互动:角色靠近装备/NPC 自动捡取/对话;白名单键和 HP/MP 正常发送 |
| 管理键(E)按下时清空非紧急队列 | 保证管理键独占执行(E 通常是闪避/强力技,不能被排队中的小技能干扰) |
| 特殊键(Space)激活时丢弃非紧急入队,但 `release:*` 与 HP/MP 仍放行 | 闪避期间不发新技能,但 TriggerMode=2 按住键释放不被卡死,救命药剂照常 |
| special_keys 不自动加入 force_move_passthrough_keys | 前者管用户物理按键透传/让路,后者管强制移动期间程序自动发键是否替换;需要同时生效就显式配置两个字段 |
| PAUSED 完全停 HP/MP + clear_queue(-1) | 用户主动暂停 = 完全停下,包括救命药剂 |
| F8/F7/F9 不在 RegisteredHooks 里 | 三个永久根热键,清理动态 Hook 时不清它们 |
| AHK 端 `ForceMoveReplacementKey` 默认硬编码 "f" | 该游戏(D4/PoE2)的默认互动键就是 f |

## 7. AHK 函数 global 完整性检查脚本

AHK v2 函数内对变量赋值会自动定为 local,**除非顶部 `global` 声明**。这是历史踩坑点(`ClearQueue` 漏声明导致 PAUSED 实际没清队列)。

定期跑这个脚本验证关键函数的 global 声明完整:

```bash
python3 << 'EOF'
import re
with open('hold_server_extended.ahk') as f: lines = f.readlines()

key_fns = {
    'ProcessQueue': {'DelayUntil','DelayClearOthers','TotalQueueCount','QueueCounts',
                     'EmergencyQueue','HighQueue','NormalQueue','LowQueue',
                     'QueueStats','IsPaused','SpecialKeysPaused'},
    'ClearQueue': {'QueueCounts','TotalQueueCount',
                   'EmergencyQueue','HighQueue','NormalQueue','LowQueue'},
    'ExecuteAction': {'DelayUntil','DelayClearOthers'},
    'EnqueueAction': {'EmergencyQueue','HighQueue','NormalQueue','LowQueue','QueueStats'},
    'ClearNonEmergencyQueues': {'HighQueue','NormalQueue','LowQueue','QueueCounts','TotalQueueCount'},
}
fn_pat = re.compile(r'^([A-Z][a-zA-Z_]*)\([^)]*\)\s*\{')
cur, fn_globals, results = None, [], []
for line in lines:
    m = fn_pat.match(line)
    if m:
        if cur: results.append((cur, fn_globals))
        cur, fn_globals = m.group(1), []
    elif cur and line.strip().startswith('global '):
        for v in line.strip().replace('global ', '').rstrip(',').split(','):
            v = v.strip()
            if v: fn_globals.append(v.split(':=')[0].strip())
if cur: results.append((cur, fn_globals))

for fn, decl in results:
    if fn in key_fns:
        miss = key_fns[fn] - set(decl)
        print(f"{'OK' if not miss else 'MISS'}: {fn}  缺: {miss or '无'}")
EOF
```

## 8. 数据流总览

```
[屏幕] ──DXGI──► [C++ 共享内存] ──ctypes──► BorderFrameManager.get_current_frame()
                                                    │
                                                    ▼
                              SkillManager.check_cooldowns(frame) / check_resources(frame)
                                                    │
                                                    ▼
                              decision: 该按 q? 该喝 HP?
                                                    │
                                                    ▼
                              AHKInputHandler.execute_skill_high("q") / execute_hp_potion("1")
                                                    │
                                                    ▼
                              AHKCommandSender.send_key("q", priority=1)
                                                    │
                                                    ▼ WM_COPYDATA
                              hold_server.EnqueueAction(1, "press:q")
                                                    │
                                                    ▼ ProcessQueue (20ms)
                              SendPress("q") → SendInput
                                                    │
                                                    ▼
                                                 [游戏窗口]
```

事件反向:
```
[键盘 F8] ──Hook──► HandleInterceptKey("F8") ──WM_COPYDATA──►
  → AHKEventFilter.nativeEventFilter → ahk_signal_bridge.ahk_event.emit
  → AHKInputHandler._on_ahk_event → event_bus.publish("intercept_key_down", key="F8")
  → MacroEngine._handle_ahk_intercept_key → _handle_f8_press → _set_state(READY)
```

## 9. 线程模型

| 线程 | 职责 |
|------|------|
| Qt 主线程 | UI、WM_COPYDATA 接收(过滤器在主线程跑)、状态切换 |
| `UnifiedScheduler` 线程 | 单线程串行调度所有定时任务(`monotonic` + `heapq`) |
| `BorderFrameManager` 内线程 | C++ 捕获回调线程(可选,目前帧拉取由调度器触发) |
| `EventBus` 线程池 | `publish_async` 用,`max_workers=6`,有递归保护 + 并发上限 |
| `SimpleAffixRerollManager` / `PathfindingManager` | 各自独立线程(被洗练/寻路使用) |
| AHK 进程内 | `SetTimer(ProcessQueue, 20)` + Hook 回调 |

跨线程通信全部走 EventBus 或 SignalBridge,避免直接持有锁跨线程。
